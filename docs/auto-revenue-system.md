# 週10万円 自動収益システム 設計書

Regional Lab 株式会社 / 作成: Claude Code / 対象ブランチ: `claude/auto-revenue-system-fs1vm5`

---

## 0. 最初に — 正直な前提

**AI 単体は、それだけでは1円も生みません。** お金は必ず「誰かが買う」ことで発生し、
その決済には法人格・口座・契約という人間側の器が要ります。ここを誤魔化した計画は必ず絵に描いた餅になります。

なので本設計の狙いは「AI が金を稼ぐ」ではなく、こう置き換えます。

> **売上に必要な作業のうち、人間にしかできない部分を極限まで削り、
> 残りを AI が指示なしで週次で回し続ける。決済は Stripe で自動化し、
> 木寺さんの作業を「承認クリック」だけに圧縮する。**

この形なら、週10万円は現実的な射程に入ります。ただし**初週から10万円は出ません。**
立ち上がりは §5 のランプ計画を見てください。

## 1. 目標の分解

```
週 100,000円  =  月 434,524円  =  年 5,214,000円
```

Regional Lab の4事業をそのまま使い、次の配分で組みます（価格は**叩き台**。確定価格に差し替えてください）。

| 種別 | 事業 | 商品 | 単価 | 必要数/月 | 月額 |
| --- | --- | --- | ---: | ---: | ---: |
| 継続 | Re.Lab | スタンダード会員（月額） | ¥4,980 | 40名 | ¥199,200 |
| 継続 | Re.Event | Event Lab 主催者プラン（月額） | ¥9,800 | 8社 | ¥78,400 |
| 都度 | Re.Com | AIリテラシー研修（法人・単発） | ¥120,000 | 1件 | ¥120,000 |
| 都度 | Regional. | EC 伝統工芸品（1点あたり粗利） | ¥3,000 | 12点 | ¥36,000 |
| | | | | **合計** | **¥433,600** |

### なぜこの配分か

- **継続課金が64%（¥277,600）**。ここが売上の「床」になります。営業がゼロの週でも
  週6.4万円は自動的に入る。**「週10万円」を"毎週"にするには、継続課金の比率が本質です。**
- **都度売上は Re.Com に寄せる**。単価12万円は、1件取れば月間ギャップの28%を一気に埋める。
  Re.Lab スタンダードで同額を稼ぐには24名の新規獲得が要る ── 労力対効果が桁で違います。
- **Regional. の EC は「自動化の相性」で採用**。在庫と発送は人の手が要るが、
  商品説明文・SNS 投稿・LP は AI が全部書ける。少額だが手離れは良い。

## 2. 自動化の境界線（ここが設計の核心）

### 2-1. 私（AI）が、指示なしで完結できること

| 領域 | 具体的な出力 |
| --- | --- |
| 集客 | 検索需要調査 → SEO記事の執筆 → サイトへ push（GitHub Pages なので push = 公開） |
| 集客 | SNS 投稿文、イベント告知文、プレスリリース原稿 |
| 営業準備 | 法人リストの調査・スコアリング（公開情報のみ）→ 提案書・見積書ドラフト生成 |
| 商品 | LP、料金ページ、申込フォーム、Stripe 決済導線の実装 |
| 顧客維持 | 会員向けコンテンツ、ナーチャリング文面、解約防止フォローの文面 |
| 経営 | KPI 集計、目標差分の算出、翌週の打ち手の提案（`automation/kpi.mjs`） |
| 改善 | サイトの改修、A/Bテスト実装、表示速度・SEO の技術改善 |

### 2-2. 私が絶対にできないこと（木寺さんが必要）

| できないこと | 理由 |
| --- | --- |
| 契約・請求・入金の名義行為 | 法人格が要る。AI に法的な当事者能力はない |
| 営業電話・商談・研修の実施 | 対面／リアルタイムの人間の仕事 |
| 商品の仕入れ・検品・発送 | 物理作業 |
| **メールの送信ボタンを押す** | **意図的に人間に残します**（§2-3） |
| 銀行・Stripe アカウントの開設 | 本人確認が要る |

### 2-3. 「送信」を人間に残す理由

私に営業メールの一斉送信までやらせるのは、技術的には可能ですが**やりません**。

- 日本の**特定電子メール法**は、事前同意のない広告メール送信を原則禁止しています（オプトイン規制）。
- 無差別送信はドメイン評価を焼き、`regional-lab.info` からのメールが全部迷惑メール判定される。
  これは**一度壊れると回復に数か月かかる、取り返しのつかない損失**です。

したがって設計は「AI が宛先と文面を用意し、人間が1件ずつ見て送る」形にします。
**木寺さんの週次作業は、この承認だけで済みます（実測で週30〜60分の想定）。**

## 3. 週次サイクル（私が自動で回す1週間）

実体は `automation/standing-order.md`（常設指示書）です。

| 曜日 | 私がやること | 木寺さんの作業 |
| --- | --- | --- |
| 月 | SEO記事2本を生成 → サイトへ公開。検索順位を記録 | なし |
| 火 | 法人20社をリサーチ・スコアリング → 上位5社の提案書ドラフト生成 | **5通を確認して送信（15分）** |
| 水 | Re.Lab 無料層 → 有料層の引き上げ施策。ナーチャ文面・LP改善 | 配信の承認（5分） |
| 木 | Event Lab 主催者向け素材、Regional. の商品説明文・SNS投稿文を生成 | 投稿の承認（10分） |
| 金 | **KPIレポート自動生成**。目標差分と翌週の打ち手3つを提示 | レポートを読む（10分） |

木寺さんの合計: **週40分程度**。それ以外は指示なしで動きます。

## 4. 集客エンジン ── SEO を主軸に置く理由

広告は止めた瞬間に流入がゼロになりますが、**記事は書いた分だけ資産として積み上がり、
書いた後は放置しても集客し続けます。** 「私が指示なしで無限に生産できるもの」で、
かつ「積み上がるもの」は記事しかありません。だから主軸はSEOです。

狙う検索キーワード群（各事業への導線）:

| キーワード群の例 | 流入する人 | 送り先 |
| --- | --- | --- |
| 「南魚沼 補助金」「新潟 地方創生 事例」 | 自治体・地元企業 | Re.Com（AI研修） |
| 「AI研修 費用 中小企業」「生成AI 社内研修 新潟」 | 経営者 | Re.Com（AI研修） |
| 「ビジコン 大学生 2026」「地方創生 インターン」 | 学生 | Re.Lab（無料→有料） |
| 「イベント 集客 できない」「学生 集客 方法」 | イベント主催者 | Event Lab |
| 「南魚沼 特産品」「伝統工芸 ギフト」 | 一般消費者 | Regional. EC |

週2本 × 26週 = **半年で52本**。日本語のニッチな地域キーワードは競合が薄く、
半年あれば上位表示は十分に狙えます。**ただしSEOは3〜6か月遅れて効く** ──
これが §5 のランプが後半で立ち上がる理由です。

## 5. ランプ計画（正直な見通し）

| 期間 | 週次収入の目安 | 何が起きているか |
| --- | ---: | --- |
| 1か月目 | ¥0 〜 ¥20,000 | 基盤構築期。決済導線・料金ページ・記事20本。売上はほぼ立たない |
| 2〜3か月目 | ¥30,000 〜 ¥60,000 | Re.Com の初受注（単発12万が効く）。Re.Lab 有料が10名前後 |
| 4〜6か月目 | ¥80,000 〜 ¥120,000 | 記事のSEOが効き始め、継続課金が積み上がる。**目標到達** |
| 7か月目以降 | ¥120,000+ | 継続課金が床になり、都度売上が上乗せされる |

**「今週から週10万」を約束する計画は詐欺です。**現実的には**4〜6か月**を見てください。
その代わり、6か月目以降は継続課金が主体なので、労力を増やさずに維持できます。

## 6. 着手前に必要なもの（木寺さんの一度きりの作業）

これが揃うまで、システムは「原稿を作るだけ」で止まります。優先度順:

1. **Stripe アカウント** ── 決済の自動化はこれが前提。これが無いと入金に必ず人手が挟まる（最重要）
2. **各商品の価格決定** ── §1 の表を叩き台に。`automation/products.json` を書き換えます
3. **Google Analytics 4 / Search Console** ── 効果測定の前提。無いと改善が勘になる
4. **メール配信基盤**（Resend / SendGrid 等）── ナーチャリングの自動化に必要
5. **私の週次自動起動の設定** ── Routine（週次スケジュール）または GitHub Actions

## 7. リスクと、それへの備え

| リスク | 備え |
| --- | --- |
| AI 生成記事の品質・重複で検索評価が落ちる | 一次情報（自社イベントの実データ、南魚沼の現地情報）を必ず混ぜる。量より情報の固有性 |
| 特定電子メール法違反 | §2-3 の通り、無断一斉送信を設計から排除 |
| 生成コンテンツの事実誤り | 数字・法令・補助金情報は公開元URLを併記し、木寺さんの確認を必須にする |
| Re.Lab の解約で床が抜ける | 解約率を KPI に含め、月次で追う。5%/月を超えたら獲得より維持を優先 |
| 単発売上（Re.Com）に依存しすぎる | 継続課金比率60%を KPI の目標値に設定（`kpi.mjs` が毎週警告） |

## 8. このリポジトリに入れたもの

| ファイル | 役割 |

```bash
node automation/kpi.mjs            # 今日基準でレポート生成
node automation/kpi.mjs --no-write # 標準出力のみ
```
