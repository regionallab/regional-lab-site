# 常設指示書 — 週次オペレーション

> これは Claude（AI）が **木寺さんの指示を待たずに毎週実行する**標準手順です。
> セッション開始時にこのファイルを読み、その週の曜日に該当するブロックを実行してください。
> 判断に迷ったら「継続課金（Re.Lab / Event Lab）の積み上げ」を優先します。
> 設計の背景は `docs/auto-revenue-system.md` を参照。

## 不変のルール

1. **メールの一斉送信をしない。** 宛先と文面を用意するところまでが AI の仕事。送信は人間が1件ずつ行う（特定電子メール法／ドメイン評価の保護）。
2. **数字・法令・補助金情報には出典URLを併記する。** 確認できない数字は書かない。
3. **価格を勝手に決めない。** `automation/products.json` の価格は木寺さんの確定値。変更提案はするが、変更はしない。
4. **一次情報を必ず混ぜる。** 自社イベントの実データ、南魚沼の現地情報。汎用的な一般論だけの記事は書かない。
5. すべての成果物は `claude/auto-revenue-system-fs1vm5` ブランチにコミットする。

## 月曜 — 集客（SEO記事）

- [ ] 前週の検索順位・流入を確認（Search Console 接続後）
- [ ] `docs/auto-revenue-system.md` §4 のキーワード群から、まだ書いていないテーマを2つ選ぶ
- [ ] 記事を2本執筆し、サイトに公開（push = 公開）
- [ ] 各記事の末尾に、対応する事業への導線（CTA）を必ず1つ置く

## 火曜 — 営業準備（Re.Com が主戦場）

- [ ] 対象法人を20社リサーチ（新潟県／宮城県の中小企業、公開情報のみ）
- [ ] スコアリング: ①AI導入の余地 ②意思決定者への到達しやすさ ③地域的な接点 ④支払い能力
- [ ] 上位5社について、その会社固有の課題に触れた提案書ドラフトを生成
- [ ] `automation/outbound/YYYY-MM-DD/` に保存し、**木寺さんに「送信待ち5件」として提示**

## 水曜 — 継続課金の引き上げ（Re.Lab）

- [ ] 無料グロース層 → 有料スタンダード層への引き上げ施策を1つ実装または改善
- [ ] ナーチャリング文面を作成（配信は承認後）
- [ ] 解約率を確認。**5%/月を超えていたら、新規獲得を止めて維持施策に全振りする**

## 木曜 — Event Lab / Regional.

- [ ] Event Lab: イベント主催者向けの訴求素材・LP改善を1つ
- [ ] Regional.: 商品説明文・SNS投稿文を生成（在庫と発送は人間の領域なので触らない）

## 金曜 — 計測と次週の設計

- [ ] `node automation/kpi.mjs` を実行しレポート生成
- [ ] 週次ランレート／継続課金比率／目標差分を確認
- [ ] **翌週の打ち手を3つに絞って提示する。**多すぎる提案はしない
- [ ] レポートと成果物をコミット＆プッシュ

## 入金があったとき

`automation/revenue-log.csv` に1行追記する。

```csv
date,product_id,customer,amount_yen,note
2026-09-03,recom-training,株式会社○○,120000,AIリテラシー研修 全2回
```

`product_id` は `automation/products.json` に定義済みのものだけを使う。
未定義の商品が売れた場合は、まず `products.json` に追加を**提案**する（勝手に追加しない）。

## 木寺さんへの報告のしかた

- 週1回（金曜）にまとめる。日々の細かい報告はしない。
- 報告に含めるもの: **今週いくら積み上がったか / 目標との差 / 承認待ちの件数 / 来週の打ち手3つ**
- 承認が必要なものは、承認しやすい形（YES/NO で答えられる形）で出す。
